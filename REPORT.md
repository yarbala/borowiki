# Отчёт: что сделано

Инструмент для проверки гипотезы «разряд молнии провоцирует боровики».
Показывает только измеренное: где за последние 7 дней молнии пришлись на лес и когда.
Решение, когда ехать, остаётся за вами.

## Как запустить

```
cd ~/projects/borowiki
npm start
```

Открыть `http://localhost:8080`. С телефона — по адресу, который сервер печатает при старте.
Зависимостей нет, `npm install` не нужен. Данные обновляются при старте и дальше раз в час.

| Команда | Что делает |
|---|---|
| `npm start` | сервер |
| `npm run update` | пересобрать грозы за последние 7 суток |
| `npm run forests` | пересобрать обзорный слой лесов (нужно один раз) |
| `npm run update -- --date=2026-09-07` | снимок состояния на ту дату (~7 минут) |
| `npm run region -- Гродно` | перенести всю область данных в другое место (~8 минут) |

## Что на экране

- **Зелёное** — все леса в радиусе 200 км от Вроцлава.
- **Молния в кружке** — место, где разряды пришлись на лес. Рядом залит сам контур леса.
- **Цвет — свежесть:** самая новая молния самая красная и крупная, недельной давности — бледная.
- **Кнопка ⚡** — все разряды за неделю, включая поля. Видно путь грозы.
- **Кнопка с каплей** — осадки по всему региону: цвет по **самому сильному дождю за окно**,
  а не по сумме, чтобы сравнивать с грозой, которая тоже событие. Нажатие на ячейку
  показывает «11.2 мм · вчера · за неделю 22.2 мм». Это контроль: видно, где дождь был
  такой же, но молний не было.
- **Кнопка с календарём** — состояние на прошлую дату.
- **Список снизу** — от самых свежих гроз к старым, с расстоянием от дома.
- **Карточка** — дата и время грозы, сколько дней прошло, площадь и сила разрядов, дождь в грозу
  и после неё, температура, график за месяц, «Маршрут», «Нашёл / Пусто».

Отметки «Нашёл / Пусто» пишутся в `data/finds.json` вместе с координатами, датой грозы
и днём приезда после неё — это и есть журнал проверки гипотезы.

## Откуда данные (ключи не нужны)

| Слой | Источник |
|---|---|
| Молнии | EUMETView WMS, слой `mtg_fd:li_afa` (MTG Lightning Imager). Кадр каждые 5 минут, ~2000 кадров на неделю |
| Леса, деревни, охраняемые территории | Векторные тайлы OpenFreeMap (данные OSM), zoom 11 |
| Дождь и температура | Open-Meteo, эндпоинт forecast с `past_days=31` |
| Поиск места | Nominatim (OSM) |

Точность положения грозы — несколько километров, это предел прибора.

## Как находится «гроза над лесом»

1. Каждый 5-минутный кадр раскладывается на ячейки сетки 0,02° (≈1,4×2,2 км) с силой вспышек 0–6.
2. Для каждой ячейки копится своя история: перерыв дольше 45 минут — уже другая гроза.
   Поэтому у каждого места своё время, а не время фронта, шедшего над регионом часами.
3. Слабые ячейки отбрасываются: у слоя широкий бледный ореол, без порога «гроза» покрывала бы треть региона.
4. Оставшиеся ячейки пересекаются с контурами лесов и режутся на куски не больше ~5 км.
5. Для каждого места запрашивается дождь и температура.

## Что я сделал неправильно и исправил

Изначально я построил **модель готовности грибов**: оценка 0–100, переключатель «Сегодня / +3 / +7 дней»,
надпись «пик ожидается». Это была моя выдумка с пиком на девятый день после грозы — ни на чём
не проверенная и прямо противоречащая правилу владельца (ехать через 2–4 дня).
Я принял макет Claude Design за источник истины вместо исходной задачи. Всё это убрано.

Осталось только измеренное. Единственное «мнение» в приложении — окно 2–4 дня,
и это правило самого владельца, а не моё.

## Проверено запуском

- Привязка координат: точечный запрос по вычисленным координатам попадает в засвеченную ячейку исходного слоя.
- Чистый старт: удалил `public/data/spots.json`, `npm start` — сервер сам пересобрал данные и отдал страницу.
- Сценарий в браузере на 400×850 и 1440×900: карта, леса, метки, список, карточка, отметка,
  слой разрядов, настройки, поиск места, выбор дома по карте, перезагрузка.
- Консоль без ошибок; все запросы приложения отвечают 200.
- Отметки переживают перезапуск сервера.
- Повторное обновление — 6 секунд (первый сбор недели ~7 минут).

## Что дальше

- **Проверка гипотезы.** Нужны отметки. Когда их наберётся хотя бы пара десятков, можно будет
  посмотреть: правда ли находки чаще там, где били молнии, и на какой день после грозы.
- **Глубина истории:** молнии с 30 мая 2025, дождь и температура — около 75 дней.
  Значит, грозы прошлого сезона поднять можно, а осадки к ним — уже нет.
- **Blitzortung** дал бы точность 1–3 км вместо нескольких километров, но только живым потоком —
  данные копились бы, пока включён компьютер.
- **Названий лесных массивов** в тайлах нет, поэтому «Лес у \<деревни\>». Для навигации это даже удобнее.
- Сервис EUMETSAT иногда отвечает 502 на отдельные кадры; после двух неудач кадр помечается
  пробелом и больше не запрашивается (в текущей неделе таких 147 из 2016).
- **Лимит Open-Meteo:** 10 000 взвешенных вызовов в сутки. Сетка дождя над лесом — это около
  600 вызовов за окно, и она кэшируется по окну, то есть при обычной работе тратится раз в сутки.
  Но несколько пересборок истории подряд лимит выбирают: 21 сентября я упёрся в него сам.
  Если снимок собрался без осадков, кнопка с каплей отключается и объясняет это; пересоберите
  снимок на следующий день командой `npm run update -- --date=ГГГГ-ММ-ДД`.
