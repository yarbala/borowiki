# План автономной разработки borowiki

Режим: пользователь даёт макет (Claude Design) и уходит. Claude сам доводит приложение до рабочего состояния, всё проверяет и оставляет отчёт. Вопросы не задаются — спорные решения принимаются по правилам ниже и записываются в отчёт.

## Концепция (финальная, 2026-09-21)

Карта показывает **точные места, где за последние 7 дней (на момент обновления) гроза прошла над лесом, и время грозы**. Регион: Вроцлав (51.1079, 17.0385) + 200 км. Больше ничего: без грибного индекса, без прогноза «+3/+7 дней», без длинной истории, без погодной сетки. Макет с крупными областями-шестиугольниками пользователь отверг — нужны реальные следы гроз.

## Данные

**Основной источник (без ключа, проверен 2026-09-21):** EUMETView WMS, слой `mtg_fd:li_afa` — MTG Lightning Imager, Accumulated Flash Area, шаг 5 минут, доступен с 2025-05-30 по текущий момент.
`https://view.eumetsat.int/geoserver/wms?service=WMS&version=1.1.1&request=GetMap&layers=mtg_fd:li_afa&srs=EPSG:4326&bbox=14.2,49.3,19.9,52.9&...&time=<ISO>`
- Проверено: запрос с диапазоном `time=a/b` НЕ объединяет кадры (возвращает один) → нужен запрос на каждый 5-минутный шаг: 2016 кадров на 7 дней при первом запуске, дальше только новые. Кэш по кадрам/дням в `data/frames/`; кадры старше 7 дней удалять.
- Точные метки времени взять из GetCapabilities (запрос на несуществующее время возвращает пустой ответ 0 байт — отличать от «грозы не было» = валидный прозрачный PNG).
- Качать вежливо: 3–4 параллельных запроса, повтор с паузой при ошибках. Оценка первого наполнения — 15–30 минут.
- Сначала попробовать получить сырые значения (WCS / `format=image/geotiff`); если нет — декодировать PNG (`pngjs`) и переводить цвет палитры в уровень интенсивности по легенде (GetLegendGraphic).
- Фиксированная сетка пикселей ~0,02° (≈1,4×2,2 км; реальное разрешение прибора над Польшей — несколько км, мельче не имеет смысла).

**Дополнительно (второй приоритет, пропустить, если не поддаётся за 30 минут):** живой сборщик Blitzortung (websocket `wss://ws*.blitzortung.org` или публичный MQTT проекта homeassistant-blitzortung) внутри сервера → точки разрядов с точностью 1–3 км в `data/strikes/ГГГГ-ММ-ДД.jsonl`. Копит только пока Mac включён; только некоммерческое использование. На карте — точки поверх следов.

**Обработка → `public/data/storms.json`:** пиксели с молниями группируются в грозы (связность в пространстве + разрыв по времени < 30 мин). У грозы: время начала/конца, список пикселей с временем первого/последнего разряда и интенсивностью, центр, ближайший город (Overpass, один запрос, кэш). Время показывать в Europe/Warsaw.

**Лес:** пересечение делается в браузере — полигоны `landcover`/`wood` из векторных тайлов OpenFreeMap (стиль Liberty, без ключа) режутся по прямоугольникам пикселей грозы; закрашивается только лес под грозой. Слой вставлять перед `waterway_tunnel` (под дороги и подписи).

**Осадки (дёшево, по клику):** карточка запрашивает у Open-Meteo (без ключа, прямо из браузера) сумму осадков в этой точке за день грозы.

## Интерфейс (макет — источник истины по виду; здесь — состав)

- Карта OSM на весь экран; лес под следом грозы закрашен. Цвет = давность: сегодня/вчера — красный → 7 дней назад — жёлтый (зелёный не использовать). Насыщенность/контур — интенсивность.
- Сверху фильтр по дням: «Все 7 дней» + 7 чипов по датам.
- Нажатие на закрашенный лес → карточка: «Гроза 18 сент., 17:40–18:25 · 3 дня назад · интенсивность высокая · ~22 мм дождя», кнопки «Маршрут» (Google Maps) и «Нашёл / Пусто» (отметка на сервер в `data/finds.json`).
- Снизу список «Грозы над лесом рядом»: ближайшие к дому в заданном радиусе, сортировка по давности; нажатие — перелёт к месту. Лес в списке определяется по уже загруженным тайлам; если для грозы леса не найдено — не показывать.
- Кнопка ⚡ — точки Blitzortung (если сборщик работает). Кнопка ◎ — моё местоположение.
- Настройки: дом (по умолчанию Вроцлав) и радиус 10–200 км, в localStorage.
- Строка статуса: «обновлено сегодня 18:05 · данные по 17:50»; предупреждение, если старше 3 часов.
- Mobile-first.

## 0. Перед стартом

1. Не дать Mac уснуть: в фоне `caffeinate -ims -t 43200`, проверить, что жив; в конце — завершить.
2. Прочитать `CLAUDE.md`, этот план и макет. Если макет противоречит плану по составу экрана — побеждает макет, расхождение записать в отчёт. Чего в макете нет — делать по этому плану.

## 1. Этапы (после каждого — проверка и git-коммит)

| # | Этап | Критерий готовности |
|---|---|---|
| 1 | `scripts/fetch-lightning.mjs`: список кадров из GetCapabilities, докачка недостающих за 7 дней, кэш, чистка старых | повторный запуск качает только новые кадры; пустой ответ ≠ «нет грозы»; сверка 2–3 кадров глазами с картинкой WMS |
| 2 | `scripts/build-storms.mjs`: кадры → грозы → `public/data/storms.json` | если за 7 дней в регионе гроз не было — проверить конвейер на более широком bbox или на датах с известной грозой (параметр `--from/--to`), затем вернуть регион; время в Europe/Warsaw корректно |
| 3 | `server.mjs`: статика, обновление при старте и каждые 30 минут, `POST /api/finds`, (опц.) сборщик Blitzortung | `curl` отдаёт страницу и данные; отметка переживает рестарт; сервер слушает 0.0.0.0 |
| 4 | Карта: MapLibre + Liberty, закраска леса под грозами, фильтр по дням | скриншот: закрашен только лес и только под следом; фильтр меняет картину; консоль без ошибок |
| 5 | Карточка, список, настройки, статус, отметки, ⚡ | каждый элемент прокликан через playwright-cli; время/дата в карточке совпадают с `storms.json` |
| 6 | Вёрстка по макету | скриншоты 400×850 и 1440×900 против макета |
| 7 | Финальная проверка и отчёт | раздел 3 |

Пустая карта — нормальное состояние (осенью гроз может не быть неделями): показать «За последние 7 дней гроз над лесами в радиусе N км не было» и дату последней грозы, если её легко получить. Для проверки и скриншотов предусмотреть режим `?demo=ГГГГ-ММ-ДД` (неделя, заканчивающаяся этой датой, из того же источника — данные есть с 2025-05-30).

## 2. Правила самостоятельных решений

- Не останавливаться на вопросах: самый простой работающий вариант + запись в отчёт.
- Сбой источника: до 3 повторов с растущей паузой, затем запасной путь (Overpass → `overpass.kumi.systems`, иначе подписи «N км на ЮЗ от Вроцлава»; WMS отдаёт ошибки → меньше параллельности; совсем недоступен → отчёт + работающий интерфейс на кэше/демо).
- Резка полигонов тормозит (> 300 мс) → на мелком масштабе рисовать пиксели грозы без пересечения с лесом, точную закраску — с zoom 9.
- Ничего не ставить глобально, не трогать файлы вне проекта, никуда не пушить. Зависимости — только локальные npm и минимум (`pngjs`; другое — с записью в отчёт).
- Одну проблему чинить не дольше ~30 минут, дальше — обход или честное «не сделано, причина».
- Коммит после каждого этапа, сообщения по-русски.

## 3. Финальная проверка (реальным запуском)

1. Чистый старт: `npm install && npm start` с нуля поднимает сервер и данные.
2. playwright-cli, 400×850 и 1440×900: карта загрузилась → скриншот; фильтр по дням; клик по закрашенному лесу → карточка, сверка с `storms.json`; осадки подгрузились; «Нашёл» → отметка на карте и в файле; список → перелёт; настройки → радиус меняет список; перезагрузка → всё на месте. При пустой неделе — то же в режиме `?demo=`.
3. `console` без ошибок, `network` без неожиданных 4xx/5xx.
4. Устаревшие данные: подменить время в `storms.json` → предупреждение в статусе.
5. Адрес для телефона `http://<ip>:8080` — в отчёт.

## 4. Что останется после работы

Работающий сервер в фоне; `REPORT.md` (сделано, скриншоты в `docs/screens/`, решения, несделанное); обновлённый `CLAUDE.md` (стек, команды); git-история по этапам; `caffeinate` завершён.

1. Макет Claude Design (и пометка, что в нём набросок).

3. Mac на зарядке, крышка открыта. Ключи не нужны.
